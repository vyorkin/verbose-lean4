# Базовая настройка Verbose Lean

Verbose Lean предлагает множество уровней кастомизации.
Если вы знакомы с мета-программированием в Lean, вы можете рассматривать
эту библиотеку как мета-библиотеку, позволяющую строить собственную
библиотеку для преподавания.
Но в этом файле мы сосредоточимся на настройке, которая достигается без
какого-либо программирования.

## Булевы параметры настройки

В любой момент можно вывести текущую конфигурацию командой
`#print_verbose_config`.

Первый параметр настройки — код языка. Язык по умолчанию — `en`, что
обозначает мою версию английского.
Библиотека также поставляется с поддержкой французского, которая
активируется так:
```lean
setLang fr
```

Этот форк дополнительно включает неофициальный русский перевод,
активируемый так:
```lean
setLang ru
```
Он покрывает те же тактики, что английская/французская версии, включая
тактику `помощь` (`help`) и виджет с подсказками — см.
[`Verbose/Russian/Examples.lean`](Verbose/Russian/Examples.lean). См.
[`translations.ru.md`](translations.ru.md) (перевод
[`translations.md`](translations.md)) — там описаны особенности на уровне
Lean, с которыми столкнулись кириллические ключевые слова и которые не
возникают у английского/французского языков.

Затем идёт ряд булевых параметров настройки, которые можно задать
следующими командами:

* `enableUnfoldingSuggestions`/`disableUnfoldingSuggestions` — включает и
  выключает подсказки по разворачиванию определений. По умолчанию включено.
* `enableHelpTactic`/`disableHelpTactic` — включает или выключает тактику
  help. По умолчанию активирована.
* `enableWidget`/`disableWidget` — включает или выключает виджет с
  подсказками. По умолчанию активирован.
* `debugWidget` включает отладочные сообщения для виджета с подсказками.
  Команды, чтобы выключить это, нет — когда отладка больше не нужна, эту
  команду нужно просто удалить.
* `allowProvingNegationsByContradiction` отключает сообщение об ошибке,
  которое появляется, когда пользователь пытается доказать отрицание от
  противного.

## Списки деклараций

Многие параметры настройки принимают списки деклараций. Поскольку такие
списки могут быть длинными и трудночитаемыми, можно объявлять (вложенные)
списки деклараций.

Например, команде `configureUnfoldableDefs` нужен список имён деклараций.
Это декларации, разворачивание которых будет предлагать тактика help или
виджет с подсказками. Допустим, вы хотите предлагать разворачивание
`continous_at`, `continuous`, `sequentially_continuous`, `seq_tends_to`,
`seq_is_bounded`, `monotone` и `divides` (это частично составленные имена).
Можно определить списки разворачиваемых определений и настроить библиотеку
так:
```
UnfoldableDefsList FunctionStuff := continuous continuous_at sequentially_continuous

UnfoldableDefsList SequenceStuff := seq_tends_to seq_is_bounded

UnfoldableDefsList AnalysisStuff := FunctionStuff SequenceStuff monotone

configureUnfoldableDefs AnalysisStuff divides
```

Обратите внимание, как в определении `AnalysisStuff` и в строке настройки
смешиваются ранее определённые списки и отдельные имена деклараций.

Если вы определяете много списков в разных файлах, вам может пригодиться
команда `#unfoldable_defs_lists`, которая выводит все ваши списки и их
содержимое.

Этот механизм используется следующими параметрами настройки. Для каждого
указаны: команда настройки, команда, создающая список, и функция,
выводящая существующие списки.
Для чего нужны эти списки деклараций, будет описано в следующих разделах.

* Разворачиваемые определения: `configureUnfoldableDefs`/`UnfoldableDefsList`/`#unfoldable_defs_lists`
* Функции-поставщики help: `configureHelpProviders`/`HelpProviderList`/`#help_provider_lists`
* Анонимные леммы для разбиения цели:
  `configureAnonymousGoalSplittingLemmas`/`AnonymousGoalSplittingLemmasList`/`#anonymous_goal_splitting_lemmas_lists`
* Анонимные леммы для разбиения факта:
  `configureAnonymousFactSplittingLemmas`/`AnonymousFactSplittingLemmasList`/`#anonymous_fact_splitting_lemmas_lists`

* Функции-поставщики подсказок: `configureSuggestionProviders`/`SuggestionProviderList`/`#suggestions_provider_lists`
* Функции-поставщики данных: `configureDataProviders`/`DataProviderList`/`#data_provider_lists`


## Анонимные леммы

Анонимные леммы — это леммы, которые библиотека использует, не обращаясь к
их именам. Это должны быть леммы, у которых на бумаге нет названия и
которые используются неявно. Но, конечно, в Lean у них есть имена, и именно
эти имена передаются в `configureAnonymousGoalSplittingLemmas` и
`configureAnonymousFactSplittingLemmas`.

Леммы для разбиения цели — это леммы, превращающие одну цель в несколько.
Их использует тактика `Let's first prove that …` («Докажем сначала, что …»).
Хрестоматийный пример — лемма `And.intro`, которая утверждает, что для
доказательства `P ∧ Q` достаточно доказать `P` и доказать `Q`.
Библиотека также предоставляет вариант, меняющий местами `P` и `Q`, чтобы
можно было начать с доказательства `Q`. Есть аналогичные леммы, позволяющие
доказывать эквивалентность через доказательство двух импликаций. Эти четыре
леммы собраны в список лемм `LogicIntros`.

Чуть менее очевидные кандидаты в анонимные леммы для разбиения цели — лемма,
доказывающая равенство множеств через двойное включение, или леммы,
доказывающие неравенства с модулем из пар неравенств.

Леммы для разбиения факта — это леммы, которые можно использовать, чтобы
получить несколько фактов из одного. Хрестоматийный пример — разбиение
конъюнкции, но для этого в библиотеке есть отдельная выделенная поддержка.
Реальный типичный пример — лемма, разбивающая `x ≥ max a b` на `x ≥ a` и
`x ≥ b`.
Кроме того, список лемм `LogicElims` содержит леммы, доказывающие любую
комбинацию `a → b` или `b → a` из эквивалентности.

## Поставщики help и подсказок

Поставщики help — это функции, которые использует тактика `help`.
Технически их два вида: те, что предоставляют help по текущей цели, и те,
что предоставляют help по локальному предположению. Но оба вида
настраиваются одним и тем же параметром настройки.

Написать такую функцию help без навыков программирования не получится,
поэтому обсуждение того, как они устроены, выходит за рамки этого документа.
Однако легко заметить нежелательное сообщение help, найти, откуда оно
берётся, и убрать соответствующую функцию из конфигурации. Конфигурация по
умолчанию получается вызовом
`configureHelpProviders DefaultHypHelp DefaultGoalHelp`, так что можно
поискать эти два списка. Также стоит упомянуть, что они не включают функции
help, предлагающие контрапозицию или доказательство от противного, тем
более что последнее срабатывает на *любой* цели. Эти функции help
называются `helpContraposeGoal` и `helpByContradictionGoal`, так что их
можно включить так:
```
configureHelpProviders DefaultHypHelp DefaultGoalHelp helpContraposeGoal helpByContradictionGoal
```

Аналогично, виджет с подсказками использует поставщиков подсказок в
дополнение к вышеописанным поставщикам help. Их тоже нельзя написать без
навыков программирования. Но один из них можно настроить и без таких
навыков: тот, что создаёт данные для инстанцирования квантора
существования и специализации квантора всеобщности на основе текущего
выделения в info-view. Это делается с помощью так называемых поставщиков
данных. Эти поставщики данных — чисто синтаксические преобразования, без
каких-либо ограничений на типы, а затем они привязываются к типам. Текущая
конфигурация по умолчанию:
```
dataProvider mkSelf a := a

dataProvider mkHalf a := a/2

dataProvider mkAddOne a := a + 1

dataProvider mkMin a b := min a b

dataProvider mkMax a b := max a b

dataProvider mkAdd a b := a + b

/-- Default data providers for numbers type, including adding one, taking the min, max and sum
of two numbers. -/
DataProviderList NumbersDefault := mkAddOne mkMin mkMax mkAdd

configureDataProviders {
  ℝ : [mkSelf, mkHalf, NumbersDefault],
  ℕ : [mkSelf, NumbersDefault] }
```
Надеюсь, это легко понять и изменить.

## Обозначения, ограниченные областью видимости (scoped)

Некоторые фразы ограничены областью видимости конкретных пространств имён.
Примеры: `Verbose.NameLess` с фразами, которые не ссылаются на гипотезы по
имени, `Verbose.Named` с фразами, которые ссылаются на гипотезу по имени, и
`Verbose.Contradicting` для дополнительных фраз, связанных с
противоречием.
Команда `open Verbose.NameLess` или аналогичная делает их доступными для
упражнений.
