# AGENTS.md

Инструкции для AI-агентов, работающих в этом репозитории.

## О проекте

Verbose Lean — библиотека тактик и команд для [Lean 4](https://leanprover-community.github.io/),
использующих подробный, "человекочитаемый" синтаксис (на английском и французском),
максимально приближенный к обычному математическому тексту. Цель — не упростить
написание кода на Lean, а упростить перенос доказательства на Lean в традиционное
бумажное доказательство и обратно. Библиотека используется для преподавания.

Зависимость: mathlib4 (см. `lakefile.toml`, версия зафиксирована через `rev`).
Версия Lean зафиксирована в `lean-toolchain`.

## Структура репозитория

- `Verbose/Infrastructure/` — общая инфраструктура (расширения окружения,
  система help/подсказок, мультиязычный фреймворк). Языконезависимый код.
- `Verbose/Tactics/` — реализация самих тактик (языконезависимая логика),
  сгруппированы по первому слову английского синтаксиса тактики.
- `Verbose/English/` и `Verbose/French/` — синтаксис тактик на конкретном языке
  и языкозависимые пользовательские сообщения. Структура файлов в этих двух
  папках симметрична: у каждого файла в `English/` есть файл-аналог в `French/`
  с тем же именем.
  - `Statements.lean` — синтаксис для примеров/упражнений.
  - `Tactics.lean` — импортирует все statements, кроме тактики help.
  - `Help.lean` — тактика help (импортирует `Tactics.lean`, т.к. ей нужен
    синтаксис всех тактик).
  - `Widget.lean` — point-and-click виджет (использует тактику help).
  - `All.lean` — импортирует всё для данного языка.
  - `Examples.lean` / `ExampleLib.lean` — примеры и вспомогательная мини-библиотека
    (сходящиеся последовательности, непрерывные функции).
- Тесты для каждой тактики лежат прямо в её файле в `English/`/`French/`
  (отдельной папки для тестов пока нет — это осознанное временное решение).
- `getting-started.md`, `basic-configuration.md`, `translations.md`,
  `CONTRIBUTING.MD` — документация проекта, стоит свериться с ними при
  соответствующих задачах.

## Сборка и проверка

- Собрать проект: `lake build`.
- Подтянуть кэш mathlib перед первой сборкой: `lake exe cache get`
  (или `./get_cache.sh` для частичной загрузки кэша только тех файлов
  Mathlib, что реально импортируются).
- Отдельного CI с проверкой тестов нет (см. `.github/workflows/lean_action_ci.yml` —
  просто `lean-action`, запускающий сборку). **Перед завершением любой задачи
  обязательно запускай `lake build`** и убеждайся, что он проходит без ошибок —
  это единственная линия защиты от регрессий.
- Тесты — это `example`/`#guard_msgs`-подобные блоки внутри тактик-файлов
  в `English/` и `French/`; они проверяются просто как часть `lake build`.

## Соглашения и стиль

- При добавлении/изменении тактики придерживайся симметрии между `English/`
  и `French/`: изменения в одном языке почти всегда должны сопровождаться
  соответствующим изменением в другом (хотя формальной проверки этого нет).
- Языконезависимую логику помещай в `Verbose/Tactics/`, языкозависимый
  синтаксис и сообщения — в `Verbose/English/` и `Verbose/French/`.
- Синхронизация файлов `Examples.lean` между языками делается вручную —
  не забывай про неё при правке примеров.
- См. `CONTRIBUTING.MD` для более подробного описания архитектуры перед
  крупными изменениями.
